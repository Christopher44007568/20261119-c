# 半透明粒子分桶深度排序

对数千个半透明粒子做**分桶深度排序（bucket sort）**，避免每帧完整 CPU
排序，并以**每帧 CPU 全排序**为参照，逐像素比较两种顺序产生的透明混合
颜色差异——而不是只报告平均帧率。

## 运行

```bash
# 无头逻辑测试（无需浏览器）
npm test

# 可视化页面（任选其一）
node serve.js            # 然后打开 http://localhost:8080/
# 或直接双击 index.html（使用经典脚本，file:// 也可运行）
```

## 场景构造

- **交叉移动**：A、B 两股粒子沿水平方向反向移动，深度波相位相反，
  粒子在场景中反复交叉穿越（`src/simulation.js`）。
- **同深度粒子**：4 条专用车道上的粒子共享完全相同的 `z`，
  用于检验稳定顺序；每个车道 3 个以上粒子。
- 默认 3000 粒子，滑块可在 500–6000 间调整。

## 排序方法

| 实现 | 复杂度 | 顺序保证 |
| --- | --- | --- |
| CPU 全排序（参照） | O(N log N) | 严格按 `z` 降序，平局按 id |
| 分桶计数排序 | O(N + B) | 桶间严格远→近；**桶内保持数组稳定序**，同深度粒子不重排 |

渲染约定为从远到近（`z` 大 → 小）执行 straight-alpha over 混合。
分桶后只需线性计数 + 前缀偏移，不做每帧比较排序。

## 跨桶平滑

- **EMA 深度平滑**：`emaZ += (z - emaZ) * (1 - exp(-dt/τ))`，
  τ 可在 UI 调节（τ=0 关闭），用于压低深度信号中的高频噪声幅度。
- **迟滞分桶（迁移抑制的主力）**：粒子只有越过相邻桶边界额外一个
  `margin` 死区才迁移。受控抖动测试表明：当抖动幅度小于 `margin` 时，
  边界抖动产生的迁移被完全吸收（`test/engine.test.js`）；`margin=0`
  时退化为即时分桶。
- 两者职责不同：EMA 让深度数值连续，迟滞决定“何时允许换桶”。
- 迁移事件（粒子 id、源桶、目标桶、深度）实时记录并在页面列出，
  发生迁移的粒子在分桶视图中高亮为白色。

## 色差如何度量

参照帧与分桶帧都在同一个**软件 RGBA 帧缓冲**（`src/framebuffer.js`）
中以完全相同的 over 算子渲染，再逐像素比较：

- **RMSE**：三通道均方根误差（0–255），主指标。
- **平均绝对色差 / 最大像素偏差**：补充误差分布。
- **偏差 > 8 的通道占比**：可见瑕疵的覆盖范围。
- **深度逆序粒子对**：归并排序统计的结构性误差（等深粒子不计）。

页面第三张视图是**色差热图**（偏差放大 4 倍），直观显示混合差异
出现的空间位置。

## 桶数扫描

点击“重新扫描”或等待自动扫描，对**同一帧粒子状态**重放桶数
2/4/8/16/32/64/128/256，绘制 RMSE 与逆序对曲线，并给出两条对照：

- **稳定分桶（实际策略）**：桶内保持稳定顺序，体现真实量化色差。
- **桶内理想重排（误差下界）**：桶内仍按全排序规则重排；它证明
  残留色差来自“桶内不再排序”这一取舍，而非渲染管线本身。

典型测量（3000 粒子、320×200 软件缓冲，Node 24）：

| 桶数 | RMSE | 逆序粒子对 | 峰值桶粒子数 |
| --- | --- | --- | --- |
| 2 | ~2.07 | ~114 万 | ~1500 |
| 16 | ~0.83 | ~20 万 | ~440 |
| 128 | ~0.23 | ~2.6 万 | ~96 |
| 256 | ~0.14 | ~1.3 万 | ~80 |

分桶计数排序本身比 `Array.sort` 全排序快约 **30 倍**
（3000 粒子约 0.02 ms vs 0.43 ms ≈ 19×；6000 粒子约 0.03 ms vs
1.09 ms ≈ 40×，见页面 HUD 的 EMA 耗时）。

## 页面展示项

- 当前桶数量、**每桶粒子数柱状图**（含峰值/均值，展示负载均衡）。
- 全排序 vs 分桶排序双视图 + 色差热图。
- 同深度次序失配计数（稳定顺序的实时校验，正常恒为 0）。
- 跨桶迁移日志与本帧迁移数。
- FPS 与两种排序各自的耗时、加速比。
